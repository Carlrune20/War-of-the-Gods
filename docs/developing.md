## Building and running

The project is built with the [GTNH ExampleMod](https://github.com/GTNewHorizons/ExampleMod1.7.10) Gradle setup
(RetroFuturaGradle). Gradle needs JDK 25 to run, and it finds or downloads the JDKs it needs.

```
./gradlew build        # jar in build/libs
./gradlew runServer    # dev dedicated server in run/server
./gradlew runClient    # dev client
./gradlew test         # unit tests, see below
```

## Tests

Unit tests live in `src/test/java` and run with JUnit 5:

```
./gradlew test
```

They cover the logic that does not need a running game:

| Test | What it checks |
|---|---|
| `BridgeLineTest` | Bridge pieces run straight along the longer axis, from the first point, and are capped in length. |
| `WallLineTest` | Walls get posts at ends and turns, close gaps beside obstacles with short segments, and skip pieces where something already stands. |
| `BuildingTypeTest` | Building ids and old names resolve, age and faction rules, workers, housing, and upgrade timing. |
| `UnitKindTest` | Which units fight, worship or are heroes, that costs are sensible, the team colour to god mapping, and upgrade prerequisites. |
| `MapAreaTest` | Inside and outside the playable square, and the distance outside it. |
| `TerrainNoiseTest` | Terrain noise is repeatable per seed, stays in range, and changes smoothly. |
| `WebSessionsTest` | Login links work once, sessions expire and log out, and unknown tokens are refused. |
| `WebJsonTest` | The JSON messages sent to browsers have the right shape. |

The end-to-end checks are in the server smoke test described under [Continuous integration](#continuous-integration).

## Continuous integration

CI runs only when started by hand: on GitHub, open Actions > Build and test > Run workflow and pick the branch. Pushes
and pull requests don't start it, and merging doesn't wait for it. It:

1. checks formatting with Spotless
2. builds the models from their Blockbench files
3. builds the mod
4. boots a dedicated server and runs the smoke test, `.github/scripts/server-smoke-test.sh`

The smoke test boots the server five times. Each boot checks the previous one:

- **Boot 1** sets up a game with `/rts` and saves it.
- **Boot 2** checks the game and its map came back from the save intact, then starts a new game to check that numbering
  continues and the old map is replaced.
- **Boot 3** checks the web map, units and buildings. It covers town centers, a worker building and working a farm, a
  barracks training warriors and archers, a storehouse, building health down to 0, a house, a tower, levels and
  upgrades, mining gold, an explosion, and the chop and torch orders.
- **Boot 4** checks that units and buildings come back after a restart. It also checks that a team losing its town
  center gets a countdown, and that a team with neither a town center nor workers is defeated, leaving a winner.
- **Boot 5** has the computer play a team. It checks the knights' fortresses, the archery range and stables, the gods'
  temples, the stone circle and the lesser demon.

Along the way, the web checks log in with a one-time link, serve the map's blocks, and stream live state over the
WebSocket.

## Generated assets

Much of the mod's art is generated by the scripts in `tools/`. Run them again after changing their inputs.

- **Structures.** `tools/structures/generate.py` draws the building schematics into
  `assets/warofthegods/structures/<faction>`.
- **Textures.** `tools/textures/generate.py` makes the skins and small icons. The resource and tool icons are copied
  from the Minecraft 1.7.10 client jar.
- **Action icons.** `tools/textures/actions.py` draws the square icons on the build, train and upgrade buttons. Each
  building is drawn from its level 1 structure with Minecraft's block textures. Each unit's face comes from its skin,
  and each upgrade gets an item or block.
- **Box models.** `tools/models/generate.py` makes the lesser demon, Zamorak's staff and Silverlight. It writes each
  model's parts as JSON into `assets/warofthegods/models`, its texture into `textures/models`, and an item's icon,
  drawn from its model. `--preview DIR` draws each one as the game does.

## Editing models in Blockbench

The lesser, greater and black demon, the centaur, the White Knight, Black Knight, Elite Black Knight and Justiciar,
Zamorak's staff and Silverlight can be edited by hand in [Blockbench](https://www.blockbench.net/). It is free, on the
desktop or in the browser. Each is in `tools/models/blockbench/` as a `.bbmodel`, with its texture (and team mask, where
it has one) inside it.

1. **Edit.** Open the `.bbmodel` in Blockbench.
   - Each group is a part, turning about its pivot. Keep the names of the parts the game moves: legs, arms, head, jaw,
     tail, the greater and black demons' `left_wing`, `right_wing` and their `_tip`s, and the knights' `head`, `body`,
     `right_arm`, `left_arm`, `right_leg`, `left_leg`, `cape`, `skirt_front` and `skirt_back`. New groups simply stand
     still.
   - Every cube must be in a group. A cube turned on its own becomes a part of its own in the game, which stays still
     while the rest moves.
   - Group cubes only with cubes from the same group. Blockbench puts a new group inside the last cube's group, so cubes
     from elsewhere take on its turn.
   - A group whose name ends in `_glow` glows in the dark.
   - The second texture, `NAME_team.png`, is where the team's colour goes. A knight's texture is his unit's 64x64 skin,
     which goes to both gods' teams. His `plume` group, and everything in it, is drawn in his team's colour over white.
2. **Save.** Use File > Save Model, keeping the name, and put the file back in `tools/models/blockbench/`. For example,
   upload it in a pull request on GitHub, then run the workflow on that branch. The build turns it into the mod's
   model, texture and icon, commits them to the branch, and the jar that run builds has the change.
3. **Preview without building.** Run
   `python3 tools/models/blockbench.py import --into <resourcepacks>/wotg/assets/warofthegods`, with a `pack.mcmeta` in
   `<resourcepacks>/wotg/`. Turn that pack on, then press F3+T. Models and textures are read again from resource packs
   on every reload.

`python3 tools/models/blockbench.py import` writes the models into the mod's own assets. Once a `.bbmodel` has been
edited, `tools/models/generate.py` leaves that model alone. To make it from the generator again, delete the `.bbmodel`.
The greater and black demons are only made in Blockbench. Likewise, `tools/textures/generate.py` leaves alone a knight's
skin painted in Blockbench. After editing a demon, run `python3 tools/textures/actions.py` to draw its head icon again.
